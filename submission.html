Project Overview

Supply Chain Intelligence Platform is a Snowflake-native admin console that unifies operational supply-chain data behind a governed ontology and exposes AI-powered insights through a Streamlit-in-Snowflake app plus a Cortex Agent. It answers: Where are we losing on-time delivery? Which suppliers are risky? What will fail next? — all while enforcing masking, row-level access, and data-quality guardrails.

What makes it interesting

  • Ontology-first design - metrics (OTD, Fill Rate, DOI, Freight $/unit) are defined once in a semantic view, not scattered across dashboards.
  • Cortex Agent orchestration - one agent, multiple tools (Analyst, Search, custom LLM & ML procs) with an evaluation dataset for accuracy tracking.
  • Governance baked in - masking policies, row-access policies, and object tags applied to every fact table.
  • Live data quality - DMFs auto-fire on data change; violations surfaced in the UI.
  • Version-controlled ontology - a changelog table tracks breaking vs non-breaking changes to metrics/dimensions.

Feature Pages

The Streamlit console has seven pages, each targeting a different persona.

1. Executive Dashboard

Four canonical KPIs (OTD, Fill Rate, Days of Inventory, Freight/Unit), OTD by plant, bottom-15 supplier scorecard, inventory health.

Persona: Exec / VP Ops

2. AI Intelligence

Four tabs: Supplier Risk (CORTEX.COMPLETE), Document Sentiment (CORTEX.SENTIMENT), Transit Delay Predictor, AI Order Prioritization.

Persona: Analyst

3. Agent Monitoring

Live view of agent config, evaluation metrics per question, tool-usage map, and a live agent tester using CORTEX.DATA_AGENT_RUN.

Persona: AI Ops

4. Governance & Policies

Masking policies, row-access policies, object tags, persona-region access matrix.

Persona: Data Governance

5. Data Quality (DMFs)

Active DMFs, current violation counts (negative inventory, delivered-w/o-date, low fill), execution history from DATA_QUALITY_MONITORING_RESULTS.

Persona: Data Steward

6. Alerts & Anomalies

Snowflake Alerts registry, KPI alert log, 90-day OTD time series, ML.FORECAST for next 30-day order volume.

Persona: On-call / SRE

7. Ontology Management

Changelog (breaking vs non-breaking), semantic views registry, metrics & dimensions catalog, country risk index.

Persona: Ontology Owner

AI & Agent Layer

Cortex Agent

A single agent, SC_ONTOLOGY.ANALYTICS.SUPPLY_CHAIN_AGENT, orchestrates eight tools. It is exercised from Streamlit via SNOWFLAKE.CORTEX.DATA_AGENT_RUN.

Evaluation loop

Every agent run is captured via SNOWFLAKE.LOCAL.GET_AI_EVALUATION_DATA. The console shows average score per metric and per-question drill-down, sorted by lowest answer_correctness so regressions surface first.

ML & other AI functions

  • SNOWFLAKE.ML.FORECAST - 30-day order volume model
  • SNOWFLAKE.CORTEX.SENTIMENT - sentiment on the supply-chain knowledge corpus
  • SNOWFLAKE.CORTEX.CLASSIFY_TEXT - doc classification
  • SNOWFLAKE.CORTEX.COMPLETE - supplier risk report generation

import streamlit as st
from snowflake.snowpark.context import get_active_session

st.set_page_config(page_title="Supply Chain Intelligence - Admin Console", layout="wide")

session = get_active_session()

st.title("Supply Chain Intelligence Platform")
st.caption("Governed Ontology | Canonical Metrics | AI-Powered Insights | Admin Console")

page = st.sidebar.radio("Navigation", [
    "Executive Dashboard",
    "AI Intelligence",
    "Agent Monitoring & Traceability",
    "Data Governance & Policies",
    "Data Quality (DMFs)",
    "Alerts & Anomalies",
    "Ontology Management"
])

# ============================================================
# PAGE 1: EXECUTIVE DASHBOARD
# ============================================================
if page == "Executive Dashboard":
    st.header("Executive Dashboard - Canonical KPIs")

    col1, col2, col3, col4 = st.columns(4)

    otd = session.sql("""
        SELECT ROUND(COUNT(CASE WHEN actual_delivery_date <= requested_delivery_date THEN 1 END) * 100.0
            / NULLIF(COUNT(actual_delivery_date), 0), 2) AS otd
        FROM SC_ONTOLOGY.RAW.ORDERS WHERE actual_delivery_date IS NOT NULL
    """).collect()[0]['OTD']

    fill_rate = session.sql("""
        SELECT ROUND(SUM(qty_fulfilled) * 100.0 / NULLIF(SUM(qty_ordered), 0), 2) AS fr
        FROM SC_ONTOLOGY.RAW.ORDER_LINES
    """).collect()[0]['FR']

    doi = session.sql("""
        SELECT ROUND(AVG(qty_on_hand) / NULLIF(AVG(avg_daily_demand), 0), 1) AS doi
        FROM SC_ONTOLOGY.RAW.INVENTORY
    """).collect()[0]['DOI']

    freight = session.sql("""
        SELECT ROUND(AVG(freight_cost / NULLIF(qty_shipped, 0)), 2) AS fpu
        FROM SC_ONTOLOGY.RAW.SHIPMENTS
    """).collect()[0]['FPU']

    col1.metric("On-Time Delivery (OTD%)", f"{otd}%", delta="-47.05 vs 95% target", delta_color="inverse")
    col2.metric("Fill Rate", f"{fill_rate}%", delta="-31.34 vs 98% target", delta_color="inverse")
    col3.metric("Days of Inventory", f"{doi} days", delta="Target: 15-30 days")
    col4.metric("Freight Cost/Unit", f"${freight}", delta="Target: <$25", delta_color="inverse")

    st.divider()

    st.subheader("OTD by Plant")
    otd_plant = session.sql("""
        SELECT p.plant_name, p.region,
            ROUND(COUNT(CASE WHEN o.actual_delivery_date <= o.requested_delivery_date THEN 1 END) * 100.0
                / NULLIF(COUNT(o.actual_delivery_date), 0), 2) AS otd_pct
        FROM SC_ONTOLOGY.RAW.ORDERS o
        JOIN SC_ONTOLOGY.RAW.ORDER_LINES ol ON o.order_id = ol.order_id
        JOIN SC_ONTOLOGY.RAW.PLANTS p ON ol.plant_id = p.plant_id
        WHERE o.actual_delivery_date IS NOT NULL
        GROUP BY p.plant_name, p.region ORDER BY otd_pct DESC
    """).to_pandas()
    st.bar_chart(otd_plant.set_index('PLANT_NAME')['OTD_PCT'])

    col_left, col_right = st.columns(2)
    with col_left:
        st.subheader("Supplier Scorecard (Bottom 15 by OTD)")
        supplier_data = session.sql("""
            SELECT supplier_name, supplier_tier,
                ROUND(otd_pct, 1) AS otd_pct,
                ROUND(fill_rate_pct, 1) AS fill_rate_pct,
                quality_score
            FROM SC_ONTOLOGY.ADVANCED.DT_SUPPLIER_SCORECARD
            ORDER BY otd_pct ASC LIMIT 15
        """).to_pandas()
        st.dataframe(supplier_data, use_container_width=True)

    with col_right:
        st.subheader("Inventory Health")
        inv_data = session.sql("""
            SELECT plant_name, abc_class,
                ROUND(days_of_inventory, 1) AS doi,
                below_reorder_point AS below_rop,
                stockout_count
            FROM SC_ONTOLOGY.ADVANCED.DT_INVENTORY_HEALTH
            ORDER BY days_of_inventory DESC LIMIT 15
        """).to_pandas()
        st.dataframe(inv_data, use_container_width=True)

# ============================================================
# PAGE 2: AI INTELLIGENCE
# ============================================================
elif page == "AI Intelligence":
    st.header("AI-Powered Intelligence")

    ai_tab1, ai_tab2, ai_tab3, ai_tab4 = st.tabs([
        "Supplier Risk Assessment", "Document Intelligence",
        "Transit Prediction", "Order Prioritization"
    ])

    with ai_tab1:
        st.subheader("AI Supplier Risk Assessment")
        st.info("Uses CORTEX.COMPLETE to analyze supplier metrics + quality documents + country risk")
        supplier_input = st.text_input("Enter supplier name:", "Quantum Plastics")
        if st.button("Generate AI Risk Report"):
            with st.spinner("Running AI analysis (CORTEX.COMPLETE)..."):
                result = session.sql(f"""
                    SELECT SC_ONTOLOGY.ADVANCED.SUPPLIER_RISK_ASSESSMENT('{supplier_input}') AS assessment
                """).collect()[0]['ASSESSMENT']
                st.markdown(result)

    with ai_tab2:
        st.subheader("Document Sentiment & Classification")
        st.info("Uses CORTEX.SENTIMENT + CORTEX.CLASSIFY_TEXT on supply chain documents")
        sentiment_data = session.sql("""
            SELECT title, doc_type, category,
                ROUND(SNOWFLAKE.CORTEX.SENTIMENT(content), 3) AS sentiment,
                CASE WHEN SNOWFLAKE.CORTEX.SENTIMENT(content) > 0.3 THEN 'Positive'
                     WHEN SNOWFLAKE.CORTEX.SENTIMENT(content) < -0.3 THEN 'Negative'
                     ELSE 'Neutral' END AS sentiment_label
            FROM SC_ONTOLOGY.DOCUMENTS.SUPPLY_CHAIN_KNOWLEDGE
            ORDER BY sentiment ASC
        """).to_pandas()
        st.dataframe(sentiment_data, use_container_width=True)

    with ai_tab3:
        st.subheader("ML Transit Delay Prediction")
        st.info("Uses historical weather + congestion data to predict delays")
        col_o, col_d, col_w = st.columns(3)
        origin = col_o.selectbox("Origin Region", ["Asia Pacific", "Europe", "North America", "Latin America"])
        dest = col_d.selectbox("Destination Region", ["North America", "Europe", "Asia Pacific"])
        weather = col_w.selectbox("Weather Severity", ["Normal", "Moderate", "Severe", "Extreme"])
        if st.button("Predict Transit Delay"):
            pred = session.sql(f"""
                SELECT * FROM TABLE(SC_ONTOLOGY.ADVANCED.PREDICT_TRANSIT_DELAY('{origin}', '{dest}', '{weather}'))
            """).to_pandas()
            st.dataframe(pred, use_container_width=True)

    with ai_tab4:
        st.subheader("AI Order Prioritization")
        st.info("Scores pending orders by urgency: customer segment + days until due + priority")
        if st.button("Get Priority Orders"):
            priority_data = session.sql("""
                SELECT * FROM TABLE(SC_ONTOLOGY.ADVANCED.AI_PRIORITIZE_ORDERS())
            """).to_pandas()
            st.dataframe(priority_data, use_container_width=True)

# ============================================================
# PAGE 3: AGENT MONITORING & TRACEABILITY
# ============================================================
elif page == "Agent Monitoring & Traceability":
    st.header("Cortex Agent - Monitoring & Traceability")

    st.subheader("Agent Configuration")
    agent_info = session.sql("""
        DESCRIBE AGENT SC_ONTOLOGY.ANALYTICS.SUPPLY_CHAIN_AGENT
    """).to_pandas()
    st.dataframe(agent_info.head(20), use_container_width=True)

    st.divider()

    st.subheader("Evaluation Run Results")
    eval_summary = session.sql("""
        SELECT
            METRIC_NAME,
            ROUND(AVG(EVAL_AGG_SCORE), 3) AS avg_score,
            COUNT(DISTINCT INPUT_ID) AS questions_evaluated
        FROM TABLE(SNOWFLAKE.LOCAL.GET_AI_EVALUATION_DATA(
            'SC_ONTOLOGY', 'ANALYTICS', 'SUPPLY_CHAIN_AGENT', 'CORTEX AGENT', 'sc-ontology-eval-v1'
        ))
        WHERE METRIC_NAME IS NOT NULL
        GROUP BY METRIC_NAME
        ORDER BY METRIC_NAME
    """).to_pandas()
    st.dataframe(eval_summary, use_container_width=True)

    # ... (governance, DMF, alerts, ontology pages continue in the file)
    # For brevity, see streamlit_app.py in the repo for the remaining 4 pages:
    #   - Data Governance & Policies
    #   - Data Quality (DMFs)
    #   - Alerts & Anomalies
    #   - Ontology Management

Building & Operating with the CoCo CLI

Every step of this project — from scaffolding the schema to deploying the Streamlit app — can be driven from Cortex Code (CoCo) Desktop & CLI. Below are concrete scenarios used during the hackathon.

Scenario 1 — Bootstrapping the ontology from a natural-language prompt

The CoCo agent is asked to design the RAW → ADVANCED layer.

> coco
> Design a supply-chain ontology in SC_ONTOLOGY with RAW facts
  (ORDERS, ORDER_LINES, SHIPMENTS, INVENTORY, SUPPLIERS, PLANTS,
  PARTS, CUSTOMERS) and derive dynamic tables for supplier
  scorecard and inventory health. Add DMFs for negative inventory
  and null delivery dates.

CoCo invokes the agent-studio, dynamic-tables, and data-quality skills, generating DDL then executing it via snowflake_sql_execute.

Scenario 2 — Generating the semantic view + Cortex Agent

> Create a semantic view over the SC ontology with canonical
  metrics (OTD, Fill Rate, DOI, Freight/Unit) and build a Cortex
  Agent that routes procurement, logistics and cross-domain
  questions to separate analyst tools plus a Cortex Search tool
  over SUPPLY_CHAIN_KNOWLEDGE.

Skill route: agent-studio → validates the YAML with reflect_semantic_model → deploys agent + verified queries.

Scenario 3 — Scaffolding the Streamlit-in-Snowflake app

> /skill developing-with-streamlit-in-snowflake
> Build a 7-page admin console (streamlit_app.py) that surfaces
  KPIs, agent evaluation, governance policies, DMFs, alerts, and
  the ontology changelog.

> snow streamlit deploy \
    --database SC_ONTOLOGY --schema ANALYTICS \
    --name SUPPLY_CHAIN_CONSOLE

Scenario 4 — Adding governance in a single turn

> /skill data-governance
> Add MASK_FINANCIAL_DATA, MASK_CUSTOMER_PII, MASK_SUPPLIER_DETAILS
  masking policies and a RAP_REGION_FILTER row-access policy driven
  by SC_ONTOLOGY.GOVERNANCE.PERSONA_REGION_ACCESS. Tag every fact
  table with ONTOLOGY_DOMAIN, DATA_SENSITIVITY, DATA_OWNER, and
  REFRESH_FREQUENCY.

Scenario 5 — Continuous agent evaluation

> /skill evaluate-cortex-analyst
> Run the sc-ontology-eval-v1 evaluation over SUPPLY_CHAIN_AGENT
  and report questions with answer_correctness < 0.8.

Results flow back into the "Agent Monitoring" page in Streamlit.

Scenario 6 — Scheduling refresh & alerts as CoCo automations

> cortex automation create \
    --name "sc-daily-otd-check" \
    --schedule "cron 0 7 * * *" \
    --prompt "Query SC_ONTOLOGY, if OTD < 60% for yesterday send an
              alert notification to ops-slack"

Scenario 7 — Publishing this submission report

> /skill snowflake-publish-report
> Publish d:\clihackathon\submission.html to Snowflake Intelligence
  and share with role HACKATHON_JUDGES.

Scenario 8 — Debugging & troubleshooting

> /skill agent-optimization
> The agent gives generic answers for logistics questions. Audit
  tool routing and verified queries; suggest fixes.

CoCo inspects DESCRIBE AGENT, evaluation traces, and semantic-view VQRs to pinpoint the LogisticsAnalyst gap.

Judging highlights

  • Snowflake-native: zero external infra — every component (data, ML, agent, UI, governance) sits inside one account.
  • Reproducible via CoCo: the whole build was orchestrated through skills, showing CoCo CLI as the primary developer surface.
  • Trust: governance + DMFs + agent eval make the AI answers auditable, not just impressive.
  • Extensible ontology: new metrics = new rows in the semantic view + a changelog entry, not a UI rewrite.
